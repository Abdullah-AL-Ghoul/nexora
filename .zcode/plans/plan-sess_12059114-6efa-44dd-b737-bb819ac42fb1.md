# NEXORA — Restructure, Fix, Redesign, and Rebrand

## What's wrong today (confirmed by reading the code)
1. **Auto-login to Admin on every visit** — `src/lib/api.ts` `getToken()` returns the literal token `'demo'` whenever no Firebase user is signed in; `server/auth.ts` maps `demo` → **ADMIN**. `App.tsx` then calls `/api/users/me` on every mount and promotes the visitor to Admin without any credentials.
2. **Can't edit products** — `/api/products` has only POST (create) and DELETE. The admin edit form re-sends the existing unique `slug`, so editing attempts a duplicate INSERT → `UNIQUE constraint` → 500 "Save Failed". (Adding new products mostly works.)
3. **Feels like a "static image", not a real world-class site** — simulated payment theatre, hardcoded demo analytics, generic externally hot-linked Unsplash photos that can break, a plain text logo, a `reviews` table with no flow, and a cosmetic newsletter.
4. Only **one** server test exists (`pricing.test.ts`); no auth, RBAC, or CRUD tests.

## Decisions you chose
- Auth: **real accounts + guest browsing** · Payments: **sandbox labeled "Test Mode"** · Imagery: **curate & bundle locally** · Logo: **heritage seal**.

---

## Phase 1 — Real authentication (fixes auto-login)
- **DB**: add `password_hash` + `auth_provider` columns to `users` with an idempotent table migration in `server/db.ts`. Password hashing via `node:crypto` `scrypt` (no new deps).
- **Server**: add `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`. Sessions = `jose` HS256 JWTs signed with a server secret (`JWT_SECRET`, dev fallback). Roles come only from the DB (registered users = `CUSTOMER`; an email in `ADMIN_EMAILS` gets `ADMIN`).
- **`server/auth.ts`**: verify local JWT first, then Firebase ID token (kept as an optional secondary). **Remove the `demo` → ADMIN bypass entirely** — an invalid/no token means *guest*.
- **Seed an admin**: `admin@nexora.com` gets a hashed default login (`ADMIN_INITIAL_PASSWORD`, default documented in README), so you can actually log in as admin.
- **Client** (`src/lib/api.ts`, `useStore`, `App.tsx`, `LoginPage`, `Navbar`, `AdminDashboardPage`):
  - `getToken()` returns the stored session token, else Firebase token, else `''` — never `'demo'`.
  - Store `currentUser` becomes nullable (guest = `null`); add `authToken`, real `login()`/`logout()`; the mount effect only fetches `/me` when a token exists, and clears the session on 401.
  - Add a `<RequireRole role="ADMIN">` route guard for `/admin` → redirects to `/login`.
  - LoginPage: real register/login forms wired to the new endpoints; **remove the Demo Persona buttons**; keep Google as an optional secondary. Sign Out now truly clears the session.
- After this: visitors browse as guests, checkout as guest or logged-in, and only a real admin gets the Admin panel.

## Phase 2 — Product add/edit fix
- **Server**: add `PUT /api/products/:id` (full update, ADMIN/MANAGER, zod-validated). Handle slug taken by another product → `409`. Keep create/delete.
- **Client**: `api.ts` gets a `put` helper + `updateProduct(id, payload)`; `saveProduct` picks POST (new) vs PUT (edit). `AdminDashboardPage.handleSaveProduct` uses it; list refreshes after save. Add + edit + delete then all work.

## Phase 3 — De-demoing: make the site feel real
- **Analytics**: compute the 7-day revenue chart + deltas from real orders in `server/routes/users.ts` (graceful fallback when DB is empty) instead of hardcoded numbers.
- **Newsletter**: add `newsletter` table + `POST /api/newsletter` (email-validated, deduped) and wire the Footer form to it.
- **Reviews**: add `GET/POST /api/products/:slug/reviews` + a real review form & list on ProductDetailPage (updates the product's `rating`/`reviews_count`).
- **Checkout**: explicitly badge the page "Test Mode" (like real sandboxes) so the simulated payment is honest.
- **404**: dedicated NotFoundPage instead of silently rendering Home.
- **index.html/SEO**: local favicon + logo, theme-color, real (env-driven) canonical.

## Phase 4 — World-class design uplift (uses ui-ux-pro-max, ui-ux-pro-max-design-system, ui-ux-pro-max-brand, ui-animation skills)
- **Heritage-seal logo** (`src/components/brand/Logo.tsx`, SVG): double-ring emblem with bezel tick marks + interlocked N/X monogram + Cinzel "NEXORA" lockup; variants (seal, lockup, monochrome). Used in Navbar, Footer, login, loader, admin, 404. Export favicon/`.svg` and an OG social card PNG (1200×630) via a rendering step.
- **Navbar**: sticky glass header that transforms on scroll, announcement bar, refined active states; brand lockup replaces the text-only placeholder.
- **Home**: polished hero with smooth Ken Burns crossfade, a luxury marquee strip, refined Ateliers cards, editorial "constitution" split section, testimonials, featured collections.
- **Micro-interactions**: hover lifts/image-swap on product cards, quick-add, scroll-reveal via IntersectionObserver + CSS classes (all respecting `prefers-reduced-motion`), refined shadows/borders/spacing; RTL/Arabic (Cairo) polish.
- Everything stays inside the existing token system in `src/index.css` (no new color/font per-component).

## Phase 5 — Bundle curated imagery locally
- Write `scripts/bundle-images.mjs`: extract unique image URLs from `seedData.ts`, `db.ts`, `HeroSection`, and admin defaults; download a curated on-brand set into `public/img/`; rewrite all source references AND migrate the SQLite rows (`products.images`, `categories.image_url`, `users.avatar`) to `/img/...` local paths. Site no longer depends on Unsplash.

## Phase 6 — Tests (more + meaningful)

- **Server integration tests**: register/log in/log out, duplicate email, wrong password, admin role by allow-list, RBAC 401/403; products create/update/delete + slug-conflict 409; orders; coupons; newsletter; reviews; analytics.
- Run existing tests + new ones, typecheck, and production build until green.

## Phase 7 — Browser QA (web-gui-tester / browser-use skill) + wrap-up
- Full journey in a real browser: guest browse → shop → product detail → register → login (admin) → **add / edit / delete a product** → logout → guest checkout → order success → 404.
- Verify no auto-login: visiting `/admin` unauthenticated redirects to login; Navbar shows "Sign In", never an admin shortcut.
- Update `docs/EVOLUTION-REPORT.md` (Arabic) + README with new default admin credentials (to be changed in production), and commit.

## Deliverables
